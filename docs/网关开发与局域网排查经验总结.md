## 二、开发侧的关键经验

### 2.1 附件上传"成功但没送达"的根因

**现象**：`set_input_files` 不报错，但 ChatGPT 回复"看不到附件"。

**诊断**：停服后跑 `scripts/diagnose_upload.py`（profile 互斥，必须先停服），dump 出 composer 里其实有 **3 个** `<input type=file>`：

```text
input#upload-files    通用，无 accept 限制，位于 composer form 内  ← 文档类必须用这个
input#upload-photos   accept="image/*"  仅图片
input#upload-camera   accept="image/*" capture  仅拍照
```

旧选择器把 `#upload-photos` 排最前，非图片文件被塞进仅图片 input，被网页静默忽略。

**修复**：选择器顺序改为 `#upload-files` 优先；上传非图片时跳过 accept 仅图片的 input；上传后等 2 秒再输入文本（立即输入会被静默丢弃）；输入后校验 composer 文本为空则重试。

**经验**：浏览器自动化里"API 调用成功 ≠ 业务生效"，必须有**业务级验证**（让模型回读附件内容）；DOM 结构要用诊断脚本实测，不能靠记忆。

### 2.2 worker 池死页面自愈

**现象**：冒烟测试中 `/v1/chat/completions` 随机 500：`Page.goto: Target page, context or browser has been closed`。某个池页面（可见 Chrome 标签）被关掉后，该 worker 永久坏到重启。

**修复**（`src/api/session_service.py`）：取 worker 先 `page.is_closed()` 检查，死了就 `new_page()` 重建；请求中途因页面死亡失败，重建后重试一次。

### 2.3 ChatGPT 生成卡死（stall）检测

**现象**：超时截图显示回复文本早已完整输出，但 stop 按钮不消失、copy 按钮不出现（后端流挂起）。原检测器要等满 120s（copy 策略）+120s（stop 策略）才落到文本稳定兜底，HTTP 客户端 240s 超时。

**修复**（`src/chatgpt/detector.py`）：快照增加 `hasStopButton`；新回合文本稳定 20s 且 stop 按钮仍在 → 判定 stall，点击 stop 释放页面并视为完成；stop 策略上限收紧到 45s。

### 2.4 测试体系约定

- `pytest`（tests/，36 用例，无需浏览器）：数据库、鉴权、隔离、上传下载、配额、会话池路由、清理任务。
- `scripts/smoke_test.py`（对**运行中**服务，23 项）：`--token2` 启用多用户隔离，`--no-live` 跳过真实发消息。
- 每次涉及 DOM 的改动后：先诊断脚本看结构，再真实浏览器跑一遍 `/v1/sessions/{id}/messages`。

## 三、局域网跨设备访问排查全过程（重点）

### 0. 症状

同一局域网的 WiFi 设备访问服务：

```text
C:\Users\20230131> curl http://192.168.8.222:5061/healthz
curl: (56) Recv failure: Connection was reset
```

本机访问一切正常。

### 1. 确认服务绑定（排除"只监听回环"）

```text
TCP    192.168.8.222:5061     0.0.0.0:0    LISTENING    43504
```

服务绑定在局域网 IP 上，绑定没问题。

### 2. 查防火墙：第一结论

```text
防火墙三配置(Domain/Private/Public)：全部 Enabled=True
放行 5061 的入站规则数：0
当前网络配置文件：Public（最严格，默认拒绝一切未放行入站）
```

结论一：**服务机 Windows 防火墙没有 5061 入站放行规则**。本机访问走内部路径不经过入站过滤，所以正常；外部包被拒。Windows 拒绝对外表现为发 RST，因此客户端报 `Connection was reset` 而不是超时——**reset 说明包到达了服务器、被主动拒绝；timeout 才指向路由/静默丢弃**。这是贯穿全程的判读钥匙。

### 3. 权限与"加错机器"两个坑

- 我的 shell 非管理员，`New-NetFirewallRule` 直接报 **错误 5 拒绝访问**。
- 用户第一次手动加规则，加在了 **LENOVO 那台客户端**（提示符 `C:\Users\LENOVO`），而规则是**机器级**的，加在客户端对服务器无效。

**经验**：加防火墙规则前先 `hostname` 确认机器（服务机是 DESKTOP-3F5PK8M）。

后来形成的免切换提权办法（在服务机内部发起，UAC 弹窗由人点「是」）：

```powershell
Start-Process -Verb RunAs powershell.exe -ArgumentList '-NoProfile -Command <无空格命令>'
```

参数里避免空格和引号以免嵌套转义；发起后轮询验证规则是否出现。

### 4. 规则加对了，仍然 reset：网段疑云

在服务机加规则 `RemoteAddress 192.168.8.0/24` 后，WiFi 客户端仍 reset。取客户端网络信息：

```text
IPv4 地址 . . . . : 192.168.9.63
子网掩码  . . . . : 255.255.252.0      ← /22！
默认网关  . . . . : 192.168.8.1
```

局域网实际是 **/22**（192.168.8.0–192.168.11.255），WiFi 设备落在 .9.x，而规则只放行 .8.x。把规则改到 `192.168.8.0/22`——**仍然 reset**。再放到 `Any`——**仍然 reset**。

**经验**：地址白名单逐次放大仍无效，就要停止"放大网段"的直觉操作，改做排除法。

### 5. 排除法：安全软件 / TUN / block 规则

```text
可疑安全软件进程（360/火绒/电脑管家/卡巴等）：无
活动网卡：仅 Realtek 有线（无 TUN 虚拟网卡，排除代理软件劫持）
生效的入站 Block 规则（带端口）：无
```

### 6. 关键证据三连：定位"路由器注入 RST"

让客户端再测，同时在服务机取证：

1. **服务机 netstat 出现大量来自客户端的 ESTABLISHED**：

   ```text
   TCP  192.168.8.222:5061  192.168.9.63:51213  ESTABLISHED  43504
   TCP  192.168.8.222:5061  192.168.9.63:53327  ESTABLISHED  43504
   ...（共 15 条，历次失败尝试的残留）
   ```

   → **TCP 握手已经完成**，防火墙放行规则在起作用；reset 发生在连接建立之后。

2. **防火墙丢弃日志（开启 droppedconnections 后）没有任何 5061 记录** → Windows 防火墙全程没丢包，彻底洗清。

3. 服务端 socket 永远停在 ESTABLISHED → 服务端从未收到 FIN/RST → 客户端看到的 RST **不是服务器发的**，是**路径上的路由器伪造注入**的。

   （顺带解释另一个迷惑现象：客户端 `ping 192.168.8.222` 超时——那是 Public 配置默认禁 ICMP 回显，与本案无关，ping 不能作为连通性判据。）

### 7. 根因：子网掩码不对称 → 不对称路由

```text
服务机：192.168.8.222 /24（静态配置，PrefixOrigin=Manual）
客户端：192.168.9.63   /22
```

- 客户端按 /22 认为服务器"同网段"，**SYN 直接二层送达**（不经过路由器）；
- 服务器按 /24 认为 .9.x 是外网段，**回包发给默认网关 192.168.8.1**；
- 路由器只看见"只有回向、没有去向"的流，其状态检测（SPI）判定异常，向客户端注入 RST。

### 8. 根治：把服务机掩码改成 /22

```powershell
Set-NetIPAddress -InterfaceIndex 4 -IPAddress 192.168.8.222 -PrefixLength 22
```

改完两侧同掩码，服务器直接二层回复客户端，路由器退出数据路径，注入点消失。

改后回归：默认路由仍在（外网/ChatGPT 不受影响）、本机 healthz 与 pool 正常。客户端 `curl.exe http://192.168.8.222:5061/healthz` 应返回 `{"status":"ok"}`；若仍异常，下一步用 `pktmon` 抓包看 RST 的源 MAC 一锤定音。

> 备注：掩码改动对静态 IP 是安全可逆的；若网卡是 DHCP 则不要这么改，应去路由器侧统一网段规划。

## 四、经验清单（可直接抄走的结论）

1. **reset vs timeout 是第一判据**：reset = 包到了、被主动拒绝（防火墙/中间盒）；timeout = 静默丢弃或路由不通。
2. **防火墙规则是机器级的**：在哪台机器加只在哪台生效；操作前先 `hostname`。
3. **本机通 ≠ 外部通**：本机访问不走入站过滤；跨机测试才是真测试。
4. **Windows 拒入站 TCP 常发 RST**，别一见 reset 就怀疑服务崩溃。
5. **白名单放大无效就停手做排除法**：AV/TUN/block 规则/丢弃日志逐项排除。
6. **netstat 的 ESTABLISHED 残留 + 服务端丢弃日志为空 = 中间盒注入 RST** 的典型指纹。
7. **子网掩码不对称会造成不对称路由**；去包直连、回包绕路由时，路由器 SPI 可能注入 RST。统一掩码（或让服务器掩码覆盖客户端网段）即可。
8. **ping 不通不代表 TCP 不通**：Windows Public 配置默认禁 ICMP 回显。
9. **PowerShell 里 `curl` 是 Invoke-WebRequest 别名**，报错形态不同；真 curl 用 `curl.exe`。
10. **非管理员 shell 的提权姿势**：`Start-Process -Verb RunAs ... -ArgumentList '-NoProfile -Command 无空格命令'`，人点 UAC，脚本轮询验证。
11. 浏览器自动化要**业务级验证**（让模型回读附件），并保留诊断脚本应对前端改版。
12. 池化浏览器页面会"静默死亡"（标签被关/崩溃），池必须自愈；长流会 stall，完成检测要有文本稳定兜底。

## 五、常用命令速查

```powershell
# 服务机：查监听 / 查规则 / 查掩码
netstat -ano | findstr :5061
Get-NetFirewallRule -Direction Inbound -Action Allow -Enabled True |
  Get-NetFirewallPortFilter | Where-Object LocalPort -eq '5061'
Get-NetIPAddress -IPAddress 192.168.8.222 | Select IPAddress,PrefixLength

# 服务机（管理员）：放行 5061
New-NetFirewallRule -DisplayName CatGPT-Gateway-5061-LAN -Direction Inbound `
  -Action Allow -Protocol TCP -LocalPort 5061 -RemoteAddress 192.168.8.0/22

# 服务机（管理员）：掩码改 /22（静态 IP 才可）
Set-NetIPAddress -InterfaceIndex 4 -IPAddress 192.168.8.222 -PrefixLength 22

# 服务机（管理员）：开启防火墙丢弃日志
netsh advfirewall set allprofiles logging droppedconnections enable
# 日志：%systemroot%\system32\LogFiles\Firewall\pfirewall.log

# 客户端：真实 curl 测试
curl.exe http://192.168.8.222:5061/healthz

# 项目内：回归
.venv\Scripts\python.exe -m pytest
PYTHONPATH=. .venv\Scripts\python.exe scripts\smoke_test.py --token2 <另一用户token>
```
